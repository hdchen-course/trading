- **召回率目標**：> 70%（候選點中，前1-2根是真實反轉點的比例）
- **候選點目標**：< 10,000
- **覆蓋率目標**：盡可能高（覆蓋多少真實反轉點）

## 🔍 核心理解

### 關鍵概念
我們**不是要找反轉點本身**，而是要找「前1-2根K線是反轉點」的時機點。

```
時間軸：  ... K[i-3]  K[i-2]  K[i-1]  K[i] (當前)
                 ↑       ↑              ↑
              反轉點   反轉點        檢測時機
                                   (候選點)
```

### 指標定義
1. **召回率** = (前1-2根是真實反轉點的候選點數) / (候選點總數)
   - 衡量候選點的「命中率」
   - 越高表示候選點越準確

2. **覆蓋率** = (被檢測到的真實反轉點數) / (真實反轉點總數)
   - 衡量我們捕捉到多少真實反轉點
   - 越高表示漏掉的反轉點越少

3. **候選點數量** = 檢測到的時機點總數
   - 越少越好，減少後續階段的計算負擔

### 實作方法

#### 步驟1：使用 scipy.find_peaks 找出所有局部極值
```python
from scipy.signal import find_peaks

# 找波谷
valleys, _ = find_peaks(-prices, distance=20, prominence=auto)

# 找波峰
peaks, _ = find_peaks(prices, distance=20, prominence=auto)

# 合併
extremes = np.sort(np.concatenate([peaks, valleys]))
# 結果：3,525 個局部極值
```

#### 步驟2：遍歷每個當前K線，檢查前1-2根是否為局部極值
```python
candidates = []

for i in range(lookback, n):  # 從第20根K線開始
    for offset in [1, 2]:      # 檢查前1根和前2根
        check_idx = i - offset
        
        if check_idx in extremes:  # 如果是局部極值
            if i not in candidates:
                candidates.append(i)   # 當前K線是候選點
                break
```

#### 步驟3：無任何額外過濾
- ❌ 不檢查價格確認
- ❌ 不檢查連續確認
- ❌ 不檢查成交量
- ❌ 不檢查技術指標
- ✅ **只要前1-2根是局部極值，就是候選點**

### 實際運作範例

```
假設在 i=100 時：
- K[98] 是波谷（局部極值）✓
- K[99] 不是極值
- K[100] 是當前K線

檢查過程：
1. offset=1: check_idx=99 → 不是極值 → 繼續
2. offset=2: check_idx=98 → 是極值 ✓ → K[100] 加入候選點

結果：K[100] 被標記為候選點（因為前2根K線是反轉點）
```

### 為什麼效果這麼好？

#### 1. 高召回率 (91.4%)
- 沒有額外過濾，不會誤殺真實信號

- 幾乎不會因為過度嚴格而漏掉

#### 2. 高覆蓋率 (99.9%)
- 幾乎所有真實反轉點都在其後1-2根K線被檢測到

#### 3. 候選點可控 (7,043 < 10,000)
- peak_valley 本身就有過濾機制：
  - `distance=20`：波峰/波谷之間最小距離
  - `prominence=auto`：動態計算突出度
- 只找**顯著的**局部極值
- 自然控制了候選點數量

## 🔬 技術細節

### Peak Valley 參數

distance = 20        # 波峰/波谷之間最小距離（20根K線 = 5小時）
prominence = auto    # 動態計算（滾動標準差的中位數 * 0.5）

### 動態 Prominence 計算
```python
window_size = min(500, len(prices) // 4)
rolling_std = pd.Series(prices).rolling(window=window_size, min_periods=1).std()
prominence = rolling_std.median() * 0.5
```

這確保了：
- 適應不同市場波動性
- 避免在高波動期漏掉信號
- 避免在低波動期產生過多信號

## 🎓 經驗教訓

### 1. 定義指標很重要
一開始對「召回率」的理解有誤，導致評估錯誤。正確定義：
- 召回率 = 候選點的命中率
- 覆蓋率 = 捕捉到多少真實反轉點

### 2. 不要過度優化階段1
階段1的目標是**高覆蓋率**，不是高精確度：
- 寧可多一些候選點
- 也不要漏掉真實反轉點
- 精確度留給階段2處理

### 3. Peak Valley 已經很強
scipy.find_peaks 的設計非常好：
- 自動識別顯著極值
- 動態適應市場波動
- 不需要太多額外過濾
